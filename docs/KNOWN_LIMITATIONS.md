# KNOWN_LIMITATIONS

L1 Header and Studio compatibility, PROVEN: the contract deployed and ran in hosted Studio. Earlier note: `genvm-lint check` (GenVM v0.2.16) passes lint and validation on the contract and its header. The contract header pins `py-genlayer:1jb45aa8...` taken from GenVM v0.2.16, the version the tests run against. Whether the hosted Studio runs that GenVM version and accepts that hash was not verified. If Studio rejects it, take the header from the current Studio boilerplate; the contract body should not change, but this has not been tested.
L2 Real payouts, PARTIALLY PROVEN. In hosted Studio the payout works: the account balance was debited by `create_task` and credited again by `withdraw` (FINALIZED, returned the full amount; a separate Faucet control also moved value between accounts). Studio balances are simulated in a local database (no EVM layer or ghost contracts), so this does not prove a transfer on a real network; do that on Testnet Bradbury. Original note: `withdraw` debits, then `emit_transfer`s. Direct Mode only proves the accounting; Studio simulates balances; a real transfer on a supported network was not run. Do not treat the payout path as production-ready.
L3 Network safety. URL syntax and host patterns are checked; DNS tricks, redirects and private-network resolution are only as safe as the validators' web layer.
L4 Evidence truth. Pinning proves what a page said, not that it is accurate, original or correctly dated.
L5 Economics. `MIN_BUDGET`, the 10% bond and the 7-day timeout are reasoned placeholders. Consensus fees per round were not measured.
L6 Unsatisfiable-criteria bond harvesting (THREAT F6) is mitigated, not solved.
L7 Narrow scope: only web research tasks, at most 3 sources, 8 criteria, 1200 chars of excerpt per source, one appeal, no new evidence on appeal.
L8 Model dependence. Validators run their own model; two honest models may disagree on a borderline criterion, producing rotations rather than a verdict.
L9 API drift. Two documented examples were wrong for SDK v0.2.16 (`DynArray[...]()` construction, `status_code` vs `status`); the contract accepts both response names. Other APIs (`list[str]` arguments, `response_format="json"`, `datetime.now()` inside GenVM, `emit_transfer` to an EOA) were exercised only under Direct Mode mocks.
L10 Direct Mode mock quirk: the mocked model auto-parses JSON strings. The contract uses `response_format="json"` so both modes return a dict.
L12 Real-balance solvency: proven in hosted Studio through `solvency()` (balance equals recorded liabilities before withdrawals, zero afterwards), but Studio balances are simulated; Direct Mode does not move value between accounts, so there only the counter identity and the view's logic are tested.
L11 Unbounded growth: tasks are never deleted; `accounting()` is O(tasks) and meant for tests.
L14 Validator disagreement is real: in Studio a re-evaluation of identical evidence failed its first round (2 agree, 3 disagree) and succeeded after a leader rotation. Borderline criteria can cost extra rounds or end undetermined (then `force_inconclusive` after the timeout).
L15 Value attached to non-payable calls (for example a leftover value in the Studio UI field) is kept by the host and cannot be refunded; check `solvency().surplus` after each negative test.
L16 Bids are open: last-moment undercutting and bid copying are possible by design.
L13 FIXED and verified in Studio (`surplus` 0 after every block): in Studio, value sent with a reverted call stays on the contract (control test: sender 10 -> 9 GEN, contract 5 -> 6 GEN; earlier, 5 GEN accumulated this way). Payable methods (`create_task`, `place_bid`, `appeal`) now never revert on invalid input: they return -1 / `REFUNDED: reason`, credit the attached value to the sender's `claimable` and record the reason (`get_last_rejection`). The 5 GEN already stranded on the old deployment are unrecoverable. Whether reverts keep value on a real network is unknown; the design no longer depends on it.
L17 The pinned excerpt is the first 1200 characters of the visible text. On pages with heavy navigation (Wikipedia: menus and a list of languages) it contains no article content, so the adjudicator cannot verify claims against it; evidence pages should be short or put the relevant text first. A future version could strip navigation or pin a content window.
